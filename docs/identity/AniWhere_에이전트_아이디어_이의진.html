AI가 답을 찾는 방법

LLM이 작품 내용을 지어내지 않고, 검색된 검수 데이터만 근거로 답하도록 설계합니다.

  1. 사용자의 자연어 기억을 받습니다.
  2. 인물·외형·능력·행동·사건을 단서로 정리합니다.
  3. 질문을 벡터로 바꾸고 의미가 가까운 청크를 찾습니다.
  4. 후보를 비교하고 부족하면 추가 질문을 합니다.
  5. 확인 회차 이후 청크를 제외한 뒤 답합니다.
CHUNKING

EXPERIMENT

발표에서 보여줄 청킹 비교

A. 작품 전체를 하나로 저장

한 벡터 안에 여러 인물과 사건이 섞여 세부 장면의 의미가 희석되고, 어떤 문장이 근거인지 설명하기 어렵습니다.

B. 의미 단위로 저장 적용 방식

리바이의 외형·무기·이동 방식이 하나의 캐릭터 청크로 검색되어 더 구체적인 근거와 회차 메타데이터를 제공합니다.

TECH DIRECTION

검색 성능 개선을 위한 논의안

자연어 표현 차이와 작품 간 회차 혼동을 줄이기 위한 구성입니다. 구체적인 모델과 구현 도구는 팀 논의를 거쳐 결정합니다.

1
자연어 단서 분석

질문을 작품 찾기·회차 찾기·복습·OTT로 분류하고 작품명, 인물, 외형, 능력, 사건을 추출합니다.

2
의미 임베딩

다국어 임베딩 모델을 검토해 “힘을 물려받음”과 “능력을 계승함” 같은 표현을 가까운 벡터로 변환합니다.

3
Vector DB

의미 청크와 회차·작품 메타데이터를 저장하고 검색할 Vector DB 제품을 비교해 선택합니다.

4
하이브리드 검색

정확한 작품명·캐릭터명은 키워드로, 흐릿한 장면과 표현은 벡터로 찾아 점수를 결합합니다.

5
2단계 검색

먼저 작품을 확정하고, 선택된 작품 안의 event·episode 청크만 다시 검색해 엉뚱한 회차를 줄입니다.

6
규칙 기반 Agent

점수가 높으면 답하고, 후보가 비슷하면 추가 질문하며, 근거가 약하면 회차를 단정하지 않습니다.

SEARCH IMPROVEMENT

현재 방식에서 어떻게 좋아지나

현재 프로토타입

문자 조각 기반 임베딩과 수작업 동의어를 사용합니다. 빠르게 실행할 수 있지만 새로운 표현이 들어올 때 규칙을 계속 추가해야 하고, 전체 작품의 청크가 한 번에 경쟁해 오답이 생길 수 있습니다.

개선 방향 논의안

의미 임베딩, 키워드·벡터 혼합 검색, 작품 확정 후 회차 재검색을 검토합니다. 새로운 표현에 강해지고 작품 간 회차 혼동을 줄이는 것이 목표입니다.
