AniWhere 저장소 지도

폴더와 파일이 각각 무엇을 담당하는지, 그리고 무엇을 넣으면 안 되는지 한눈에 보는 안내서입니다. 왼쪽 트리에서 아무 항목이나 누르면 오른쪽에 설명이 나옵니다. 규칙의 원본은 AGENTS.md와 docs/ARCHITECTURE.md이고, 이 페이지는 그 내용을 보기 쉽게 옮긴 것입니다.

Git에 올림 (커밋) 올리지 않음 (코드가 다시 만듦·비밀 값) 아직 없음 · 데모 확인 후 결정
1 · 폴더 구조

각 폴더는 무엇을 담당하나

필터로 커밋하는 것과 커밋하지 않는 것만 골라 볼 수 있습니다.

2 · 흐름

데이터와 코드는 한 방향으로만 흐른다

거꾸로 흐르는 순간 "누가 이 파일을 고쳤지?"가 생깁니다. 두 흐름 모두 위에서 아래로만 갑니다.

데이터 흐름 data/

사람 손이 닿는 곳은 curated/ 하나뿐입니다. 나머지는 명령 한 번으로 다시 만들 수 있으니 Git에 올리지 않습니다.

인터넷AniList · TMDB · Kitsu · JustWatch · 팬 위키
make data · aniwhere/ingest
data/raw/받은 원본 그대로. 수정 금지 · 커밋 안 함
make index · aniwhere/chunking
＋ data/curated/ (사람이 검수한 사건·회차 보강) 합류
data/processed/청크 + 메타데이터(작품·종류·시즌·회차)
make index · aniwhere/retrieval
data/index/벡터 DB. 질문이 들어오면 여기서 검색

코드 의존 방향 aniwhere/

아래 모듈은 위 모듈을 써도 되지만, 위 모듈이 아래 모듈을 부르면 안 됩니다. records/는 모든 단계가 "어디까지 봤나"를 읽는 중심 기억입니다.

ingest/외부에서 데이터 수집
쓴다
chunking/기억 단위로 자르기
쓴다
retrieval/검색 + 스포일러 필터 (검색 전에 제외)
쓴다
＋ records/ (본 회차) 를 읽어 스포일러 범위 결정
agent/의도 파악 · 도구 선택 · 추가 질문 · 답변
쓴다
api/ 또는 app/화면과의 입구. 판단 로직 금지 (예정)
3 · 헷갈릴 때

이 파일, 어디에 둘까

새 파일을 만들기 전에 아래 질문 중 "예"가 나오는 곳에 둡니다.

사람이 직접 쓰거나 검수한 데이터인가?

data/curated/

코드를 돌리면 다시 생기는 데이터인가?

data/raw · processed · index

반복 실행되고 매번 같은 결과가 나와야 하는 코드인가?

aniwhere/

한 번 해보는 실험·비교인가?

notebooks/

숫자나 이름만 바뀌는 값인가? (작품 목록, top_k, 모델명)

config/settings.yaml

API 키 같은 비밀 값인가?

.env (커밋 금지)

"얼마나 잘 찾나"를 숫자로 재는가?

eval/

"고장 났나"를 확인하는가?

tests/

사람이 읽는 글인가? 발표용 그림인가?

docs/ · reports/figures/
4 · GitHub 협업

브랜치와 PR은 이렇게 돌아간다

과제 요구사항이 "merge log 공개"라서, 모든 변경은 PR을 거쳐 Merge commit으로 들어옵니다. 그래야 누가 무엇을 언제 합쳤는지 기록이 남습니다.

브랜치 구조

main ──●────────────●─────────── ● (보호됨: 직접 push 불가) │ ↑ ↑ └─docs/kwonjae-identity │ │ └─feat/taeho-kitsu-collect ──┘ PR → 승인 1명 → Merge commit
종류언제 쓰나
feat/새 기능
fix/버그 수정
data/curated 데이터 추가·수정
docs/문서
exp/노트북 실험
chore/설정·환경

이름 규칙: 종류/이름-주제 · 예) fix/uijin-search-ui

작업 한 번의 순서

  1. git switch main && git pull로 최신 상태 받기
  2. git switch -c feat/이름-주제로 브랜치 만들기
  3. 작업 후 make test 통과 확인
  4. git push -u origin 브랜치이름
  5. GitHub에서 PR 생성. .github/pull_request_template.md가 자동으로 채워짐: 시청 여정 몇 단계인지, 무엇·왜·어떻게 확인했는지, 키·스포일러 체크
  6. 팀원 1명 승인 → Merge commit으로 합치기 (Squash·Rebase는 꺼져 있음)
